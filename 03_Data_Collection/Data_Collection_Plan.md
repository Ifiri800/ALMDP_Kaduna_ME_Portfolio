## 1. Purpose of the Data Collection Plan

This Data Collection Plan defines the procedures for collecting, recording, reviewing, validating, managing, and preparing baseline data for the Agricultural Livelihoods and MSME Development Project (ALMDP).

The plan establishes a standardized approach for ensuring that baseline data are:

- Relevant to the ALMDP Results Framework.
- Complete and internally consistent.
- Collected using standardized definitions.
- Suitable for indicator calculation.
- Traceable from respondent-level records to reported indicators.
- Subject to documented quality assurance and data-quality controls.

# 15. Automated Validation

The dataset will be subjected to automated validation checks.

### Respondent Validation

- `respondent_id` must be unique.
- Required identification fields must be complete.
- Age must be within the approved range.
- LGA must belong to the approved ALMDP implementation LGAs.
- Beneficiary type must contain a valid category.
- Binary variables must contain valid values.

### Agricultural Validation

- `farm_area_ha` must be greater than zero for applicable farmers.
- `area_cultivated_ha` must be greater than zero where productivity is calculated.
- Agricultural quantities must not be negative.
- `quantity_sold_t` must not exceed `quantity_harvested_t`.
- `quantity_consumed_t` must not exceed `quantity_harvested_t`.
- `quantity_lost_t` must not exceed `quantity_harvested_t`.
- Total post-harvest losses must not exceed harvested quantity.

### Income Validation

- Income values must not be negative.
- `total_annual_income_ngn` must equal the sum of the applicable income components.
- Missing income components must not automatically be converted to zero.

### MSME Validation

- `annual_sales_ngn` must not be negative.
- `annual_operating_cost_ngn` must not be negative.
- `annual_profit_ngn` must equal annual sales minus annual operating costs.
- Financial-record variables must contain valid binary values.

### Knowledge Validation

- Knowledge response codes must be valid.
- Binary knowledge variables must contain only 0 or 1.
- `knowledge_score` must range from 0 to 10.
- `adequate_knowledge` must equal 1 only when `knowledge_score >= 7`.

### Resilience Validation

- Resilience responses must contain values from 1 to 4.
- Reverse-coded resilience values must fall within the expected range.
- `resilience_score` must range from 0 to 100.
- `resilience_status` must be correctly derived from the defined threshold.

# 18. Missing Data Management

Missing values will be identified during data profiling, validation, and data-quality review.

The objective of missing-data management will be to preserve data integrity while ensuring that indicator calculations are based only on valid observations.

## 18.1 Identification of Missing Data

Missing values will be identified for all variables during the data-quality assessment process.

The data review will distinguish between:

- Missing values.
- Valid zero values.
- Not applicable responses.
- Respondent refusal.
- Respondent inability to provide an answer.
- Data-entry omissions.
- Missing values resulting from questionnaire skip patterns.
- Missing values resulting from incomplete submissions.

A valid zero will not be treated as a missing value.

For example, an income component recorded as `0` will indicate that the respondent reported no income from that source, whereas a blank value will be treated as missing unless the questionnaire specifies that the variable is not applicable.

## 18.2 Classification of Missing Values

Where sufficient information is available, missing values will be classified according to their likely cause.

Potential categories will include:

| Missing Data Category | Description |
|---|---|
| Not applicable | The question does not apply to the respondent |
| Don't know | Respondent could not provide the information |
| Refused | Respondent declined to provide the information |
| Not answered | Question was applicable but no response was recorded |
| Data-entry error | Information was omitted or incorrectly entered |
| Skip-pattern missing | Question was correctly skipped based on a previous response |
| Incomplete submission | Survey or record was submitted before completion |

The classification will be recorded where necessary in the data-quality documentation.

## 18.3 Treatment of Missing Values

Missing values will not automatically be converted to zero.

A missing value will only be replaced or corrected when there is sufficient evidence to establish the correct value.

Where the correct value cannot be established, the missing value will remain missing.

The original raw value will be preserved.

Any correction to a missing value will be documented in the DQA Log.

## 18.4 Missing Values in Derived Variables

Derived variables will only be calculated when the required source variables are valid.

For example:

```text
productivity_t_per_ha =
    quantity_harvested_t
    / area_cultivated_ha

# 20. Baseline Timing

## 20.1 Baseline Timing Requirement

The baseline assessment will be conducted before substantive project implementation activities begin. The timing will ensure that baseline measurements represent the condition of the target population before beneficiaries are exposed to project-supported interventions that could influence the indicators.

The baseline will establish the initial reference values for the indicators defined in the ALMDP Results Framework and M&E Framework.

## 20.2 Purpose of Baseline Timing

The baseline timing will serve to:

- establish the starting values for outcome and impact indicators;
- provide a reference point for measuring change during implementation;
- support realistic target monitoring and performance assessment;
- establish pre-intervention beneficiary characteristics and conditions;
- provide information for planning implementation and monitoring activities;
- support disaggregation of baseline conditions by relevant beneficiary characteristics and geographic areas.

## 20.3 Relationship with Project Implementation

Baseline data collection will be completed before beneficiaries receive substantive project support that could materially affect measured outcomes.

Activities such as training, input support, market-linkage interventions, MSME business support, demonstration activities, or other interventions that may influence outcome indicators will not be treated as baseline exposure.

Where limited preparatory or administrative activities occur before baseline data collection, their timing and potential influence on baseline measurements will be documented.

## 20.4 Baseline Reference Period

The reference period for each indicator will follow its approved indicator definition and data source.

Where an indicator requires historical information, such as annual income, agricultural production, business revenue, or operating costs, the questionnaire will specify the applicable recall period.

Recall periods will be applied consistently across respondents to support comparability.

## 20.5 Baseline Indicator Values

Baseline values will be calculated using the approved definitions, numerators, denominators, units of measurement, and calculation rules contained in the Indicator Register and Indicator Reference Sheet.

Baseline calculations will be based only on valid observations after completion of data quality review and cleaning.

Missing, invalid, duplicate, or unresolved records will not be included in indicator calculations unless they meet the approved validity criteria.

## 20.6 Baseline Data Quality Review

Baseline data will undergo the established data quality assurance process before the baseline values are finalized.

The review will include:

- completeness checks;
- range and validity checks;
- logical consistency checks;
- duplicate identification;
- skip-pattern verification;
- review of missing values;
- review of extreme or unusual observations;
- recalculation of derived variables;
- verification of indicator denominators;
- review of disaggregated data;
- documentation of data quality issues and corrective actions.

Outliers will not be automatically removed. Unusual values will be investigated and retained where they are determined to be valid observations.

## 20.7 Baseline Finalization

Baseline indicator values will be finalized only after:

1. raw data have been preserved;
2. data quality checks have been completed;
3. identified errors have been corrected using documented evidence;
4. derived variables have been recalculated;
5. indicator calculations have been independently reviewed;
6. unresolved data limitations have been documented;
7. the final baseline dataset has been approved for analytical use.

The finalized baseline values will be entered into the M&E database and used as the reference values for subsequent performance monitoring.

## 20.8 Interpretation of Baseline Results

Baseline results will describe the situation of the target population at the beginning of the implementation period.

Baseline findings will not be interpreted as evidence of project-attributable change because the project intervention has not yet been implemented at substantive scale.

Subsequent monitoring and evaluation results will be compared with the baseline to assess changes in indicator performance over time.

## 20.9 Baseline and Future Performance Measurement

The baseline will provide the reference point for subsequent measurements at the outcome and impact levels.

Performance analysis will compare:

- baseline values;
- subsequent monitoring values;
- annual indicator values;
- approved targets;
- disaggregated results;
- implementation progress; and
- relevant contextual factors.

Changes observed after baseline will be interpreted using the project's monitoring evidence, implementation records, data quality information, and relevant external factors.

Routine monitoring will distinguish between observed change and project contribution. Routine monitoring data will not be used to claim direct causal attribution without an appropriate evaluation design.

## 20.10 Baseline Documentation

The baseline process and results will be documented through:

- completed baseline questionnaires;
- raw baseline dataset;
- data quality and validation records;
- DQA log;
- cleaned baseline dataset;
- data dictionary and coding documentation;
- baseline indicator calculations;
- baseline analysis;
- baseline report;
- approved baseline indicator values; and
- version-controlled analytical outputs.

All baseline documentation will maintain traceability from the original data collection records through data cleaning, indicator calculation, analysis, and reporting.

## 20.11 Baseline Use in Management

Baseline findings will be used to support:

- implementation planning;
- beneficiary targeting and profiling;
- refinement of monitoring priorities;
- identification of areas requiring additional support;
- establishment of realistic performance expectations;
- subsequent indicator tracking;
- management review and adaptive management.

# 21. Indicator Calculation

Indicator calculations will be performed using the approved definitions, variables, denominators, and calculation rules in the Results Framework, Indicator Register, Indicator Reference Sheet, Baseline Questionnaire, and Data Dictionary. All calculations will be based on validated and cleaned data.

## 21.1 General Calculation Principles

The following principles will apply to all indicators:

1. Calculations will use the approved indicator definition and unit of measurement.
2. Only valid observations will be included in indicator calculations.
3. Missing, invalid, or unresolved observations will not be converted to zero unless zero is the valid recorded value.
4. Denominators will be based on respondents or records with sufficient valid information for the specific indicator.
5. Derived variables will be recalculated after data cleaning and validation.
6. Indicator calculations will be reproducible using documented formulas and scripts.
7. Where an indicator requires a specific beneficiary group, only eligible respondents will be included.
8. Negative financial values will be retained where they represent valid reported results, such as an MSME operating loss.
9. Outliers will not be automatically removed from calculations. Unusual values will first be reviewed and documented.
10. Indicator results will be disaggregated where specified in the M&E Framework.

- Agricultural MSMEs.

This distinction will prevent indicators from being calculated using an inappropriate denominator.

For example:

- Agricultural productivity will be calculated for eligible farmers.
- MSME annual profit will be calculated for eligible MSMEs.
- Financial management indicators will use eligible MSME records.
- Farmer practice adoption indicators will use eligible farmer records.

# 24. Confidentiality and Data Protection

## 24.1 Purpose

Data confidentiality and protection measures will be applied throughout the data collection, management, analysis, reporting, and storage process. The purpose will be to protect respondents, prevent unauthorized access to information, maintain data integrity, and ensure responsible use of monitoring and evaluation data.

Before administering the questionnaire, enumerators will explain:

- The purpose of the data collection.
- Why the respondent is being asked to participate.
- The type of information being collected.
- How the information will be used.

- Poor data quality.
- Delayed reporting.

Corrective actions will be recorded and monitored until completion.

Where the corrective action does not resolve the identified problem, the issue will be escalated for further management review.
