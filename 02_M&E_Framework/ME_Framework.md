# Agricultural Livelihoods and MSME Development Project (ALMDP)
## Monitoring and Evaluation Framework

**Project Status:** Synthetic/Simulated Portfolio Project  
**Location:** Kaduna State, Nigeria  
**Implementation Period:** January 2027 – December 2030  
**Target Beneficiaries:** 10,000  
**Prepared for:** Monitoring and Evaluation Portfolio Demonstration

> **Portfolio Disclaimer:** This document describes a synthetic project developed for professional portfolio purposes. It does not represent an actual donor-funded intervention or actual project performance in Kaduna State.

---

## 1. Purpose of the M&E Framework

The Monitoring and Evaluation (M&E) Framework provides the operational structure for measuring, managing, reporting and learning from the implementation of the Agricultural Livelihoods and MSME Development Project (ALMDP).

The framework translates the project's Theory of Change and Results Framework into a practical M&E system that defines:

- what will be measured;
- how indicators will be measured;
- where data will come from;
- how frequently data will be collected;
- who will be responsible for data collection and verification;
- how data quality will be maintained;
- how information will be analysed and reported; and
- how evidence will be used for management and adaptive decision-making.

The framework covers project-level performance monitoring, baseline measurement, routine monitoring, data quality assurance, outcome measurement, evaluation, reporting, learning and evidence use.

---

## 2. M&E Objectives

The ALMDP M&E system will pursue the following objectives:

1. Establish reliable baseline values for project indicators.
2. Track progress against annual and end-of-project targets.
3. Measure project outputs, outcomes and longer-term changes.
4. Provide timely and credible performance information to project management.
5. Maintain a structured and auditable project data system.
6. Identify implementation gaps, emerging risks and performance deviations.
7. Support evidence-based corrective action and adaptive management.
8. Generate evidence for learning, accountability and reporting.
9. Ensure that project data are complete, accurate, consistent, timely and traceable.
10. Assess the contribution of project interventions to improved agricultural livelihoods and MSME performance.

---

## 3. M&E Principles

The M&E system will be guided by the following principles.

### 3.1 Results-oriented monitoring

Monitoring will focus on measurable changes across the results hierarchy rather than only tracking activities.

### 3.2 Data quality

All reported results will be subject to appropriate quality controls covering:

- accuracy;
- completeness;
- consistency;
- timeliness; and
- data integrity.

### 3.3 Disaggregation

Where applicable, data will be disaggregated by:

- sex;
- age group;
- LGA;
- beneficiary type;
- value chain;
- MSME type; and
- disability status.

### 3.4 Transparency and traceability

Reported results will be traceable from the reported result to the underlying dataset and original source records.

### 3.5 Data use

Data collection will serve a management purpose. Monitoring information will be analysed and used to identify problems, understand causes and support corrective action.

### 3.6 Ethical data management

Data will be collected and managed in accordance with informed consent, confidentiality, responsible data handling and appropriate access controls.

## 5. M&E Architecture

The ALMDP M&E architecture will connect project design, data collection, data quality assurance, analysis, reporting, and management decision-making into one integrated system.

The architecture will follow this sequence:

**Theory of Change → Results Framework → Indicator Register → Indicator Reference Sheets → Data Collection Tools → Data Dictionary and Coding Scheme → Field Data Collection → Data Validation and Quality Assurance → Clean M&E Dataset → Indicator Calculation → Analysis and Visualization → Dashboard and Reports → Management Decisions → Corrective Action → Learning and Adaptation**

Each stage will provide controlled inputs to the next stage. This will establish traceability between project results, source data, calculated indicators, reported performance, and management decisions.

### 5.1 Core M&E Components

The M&E system will comprise:

- Results Framework.
- Indicator Register.
- Indicator Reference Sheets.
- Data Collection Plan.
- Baseline Questionnaire.
- Data Dictionary.
- Variable Coding Scheme.
- Validation Rules.
- Data Quality Assurance Protocol.
- Raw and cleaned datasets.
- Indicator calculation scripts.
- Analysis workbooks and notebooks.
- Dashboard datasets.
- Performance reports.
- Lessons-learned documentation.

### 5.2 M&E Architecture Principle

The system will maintain a clear distinction between:

- **Source data** — information collected from beneficiaries, project records, field observations, and administrative records.
- **Validated data** — data that have passed defined quality checks.
- **Clean data** — validated data prepared for analysis.
- **Indicator data** — calculated measures derived from approved datasets.
- **Reported results** — performance information presented to management and stakeholders.

No reported indicator will be generated from an uncontrolled or undocumented dataset.

## 8. Data Flow

The ALMDP M&E data flow will establish a controlled pathway from data collection to management use.

The standard data flow will be:

**Data Collection → Enumerator/Field Review → Supervisor Review → Data Submission → Automated Validation → Manual Data Quality Review → Data Cleaning → Approved Dataset → Indicator Calculation → M&E Database → Dashboard and Reports → Management Review → Corrective Action and Learning**

### 8.1 Data Collection and Field Review

Enumerators or responsible project staff will collect data using approved tools. Field-level review will identify missing responses, invalid values, inconsistent responses, and incomplete records before submission.

### 8.2 Supervisor Review

Supervisors will review submitted records for completeness, logical consistency, unusual values, and adherence to data collection procedures.

Records requiring clarification or correction will be returned for documented resolution.

### 8.3 Automated Validation

Automated validation will check:

- Required fields.
- Data types.
- Valid ranges.
- Approved response categories.
- Unique respondent identifiers.
- Logical relationships between variables.
- Duplicate records.
- LGA and community coding.
- Beneficiary-type requirements.

### 8.4 Manual Quality Review and Cleaning

Data that pass automated checks will undergo manual review where necessary. Data cleaning will be documented through a data quality and cleaning log.

The original raw dataset will be retained separately and will not be overwritten during cleaning.

### 8.5 Approved Dataset and Indicator Calculation

Only an approved clean dataset will be used for official indicator calculation.

Indicator calculations will follow the approved definitions and calculation methods in the Indicator Register and Indicator Reference Sheet.

### 8.6 Reporting and Management Use

Calculated indicators will feed into analysis, dashboards, and periodic reports. Management will use the resulting evidence to identify performance gaps, investigate causes, determine corrective actions, and monitor follow-up.

## 13. Data Quality Assurance

Data Quality Assurance (DQA) will ensure that information used for management decisions and reporting is sufficiently accurate, complete, consistent, timely, and reliable.

The ALMDP DQA system will use five core quality dimensions:

1. **Accuracy** — data correctly represent the underlying activity, beneficiary, or result.
2. **Completeness** — required records and fields are sufficiently complete.
3. **Consistency** — values and relationships are logically consistent across records and sources.
4. **Timeliness** — data are collected, submitted, validated, and reported within required timelines.
5. **Integrity** — data remain protected from unauthorized alteration, loss, or manipulation.

### 13.1 DQA Controls

DQA controls will include:

- Mandatory fields.
- Range restrictions.
- Valid response categories.
- Skip logic.
- Unique respondent identifiers.
- Automated validation.
- Duplicate detection.
- Supervisor review.
- Source-document verification.
- Beneficiary verification.
- Back-checks.
- Spot checks.
- Record-to-report reconciliation.
- Periodic DQA assessments.

### 13.2 DQA Process

The DQA process will follow:

**Identify Data Requirement → Define Quality Standard → Collect Data → Validate → Review → Correct → Document → Approve → Monitor**

Data quality issues will be recorded in the DQA or validation log with sufficient information to identify the affected record, variable, issue, action taken, and resolution status.

### 13.3 DQA Performance Standard

The project will target at least **95% of sampled records passing defined DQA checks**, consistent with indicator **OP-10**.

Where DQA performance falls below the required standard, the M&E team will investigate the cause and implement corrective measures.

### 13.4 Data Quality Responsibility

Data quality will be a shared responsibility.

Enumerators and field staff will be responsible for accurate source data collection. Supervisors will conduct field-level review. M&E personnel will conduct systematic validation and DQA. Project management will ensure that identified quality issues receive appropriate corrective action.

## 16. Indicator Calculation

Indicator calculations will follow the approved definitions, units, numerators, denominators, data sources, and calculation methods documented in the Indicator Register and Indicator Reference Sheets.

Calculations will be performed using validated and approved datasets.

### 16.1 Percentage Indicators

For percentage indicators, the calculation will be:

**Percentage = (Numerator / Denominator) × 100**

The numerator and denominator will be clearly defined in the relevant indicator documentation.

Records that do not meet the denominator criteria will not be included in the calculation.

### 16.2 Average Indicators

For indicators measuring an average value:

**Average = Sum of valid observations / Number of valid observations**

Missing observations will not automatically be treated as zero.

### 16.3 Agricultural Productivity

Average crop productivity will be calculated as:

**Productivity (t/ha) = Quantity harvested (tonnes) / Area cultivated (hectares)**

Only valid observations with positive cultivated area and valid harvested quantity will be included.

### 16.4 Post-Harvest Loss Rate

Post-harvest loss rate will be calculated as:

**Post-harvest loss rate (%) = (Quantity lost / Quantity harvested) × 100**

The quantity lost will include documented post-harvest losses attributable to relevant stages such as damage, storage, transport, processing, and other identified causes.

### 16.5 Knowledge Score

The knowledge assessment will contain ten questions.

Each correct answer will receive a value of 1 and each incorrect answer will receive a value of 0.

The total knowledge score will therefore range from 0 to 10.

**Adequate knowledge = knowledge score ≥ 7**

The percentage of beneficiaries with adequate knowledge will be calculated as:

**Adequate knowledge (%) = (Beneficiaries with score ≥ 7 / Valid beneficiaries assessed) × 100**

### 16.6 Practice Adoption

The number of recommended agricultural practices adopted by each farmer will be calculated from the defined practice variables.

The adoption indicator will classify a farmer as meeting the required adoption threshold when the farmer reports adoption of at least three recommended practices.

**Adoption status = 1 if practices adopted ≥ 3; otherwise 0**

The percentage adopting at least three practices will then be calculated from valid farmer records.

### 16.7 Average Annual Beneficiary Income

Average annual beneficiary income will be calculated from valid reported annual income observations.

Income components may include:

- Crop income.
- Livestock income.
- Processing income.
- Other agricultural income.
- Business income.
- Employment income.
- Other income.

**Total annual income = Sum of valid income components**

**Average annual beneficiary income = Total valid annual income / Number of valid observations**

Missing income values will not automatically be interpreted as zero.

### 16.8 MSME Profitability

MSME annual profit will be calculated from reported annual sales and operating costs where appropriate:

**Annual profit = Annual sales − Annual operating costs**

Where a valid reported profit figure is available and the indicator definition permits its use, the documented indicator methodology will be followed consistently.

### 16.9 Indicator Calculation Controls

Indicator calculations will be subject to:

- Approved indicator definitions.
- Validated datasets.
- Documented formulas.
- Consistent denominator rules.
- Required disaggregation.
- Review of unexpected values.
- Reconciliation against source records where necessary.
- Reproducible calculation scripts or documented calculation procedures.

## 17. Performance Monitoring

Performance monitoring will compare actual achievement against approved targets and identify areas requiring management attention.

### 17.1 Target Achievement

For higher-is-better indicators:

**Target achievement (%) = (Actual value / Target value) × 100**

For lower-is-better indicators, performance will be interpreted using the approved inverse performance logic so that reductions toward the target are recognized as improvement.

### 17.2 Performance Status

A standardized RAG approach will be used for performance interpretation.

| Performance level | Status | Interpretation |
|---|---|---|
| ≥90% of target achievement | Green | On track / strong performance |
| 70–89% of target achievement | Amber | Moderate performance / management attention required |
| <70% of target achievement | Red | Significant underperformance / corrective action required |

For lower-is-better indicators, such as post-harvest loss rate, the status will be determined against the direction of the target rather than applying the higher-is-better formula directly.

### 17.3 Performance Analysis

Performance reviews will examine:

- Current achievement.
- Target.
- Variance.
- Trend.
- Geographic differences.
- Beneficiary-group differences.
- Implementation intensity.
- Data quality.
- Contextual factors.
- Corrective actions.

A performance status will not be interpreted in isolation from the underlying evidence.

### 17.4 Variance Management

Where performance is below the expected level, the M&E team will support management to:

1. Identify the variance.
2. Investigate the likely cause.
3. Review supporting evidence.
4. Agree on corrective action.
5. Assign responsibility.
6. Set a follow-up deadline.
7. Monitor implementation and subsequent performance.

- Reporting periods.

- Calculations.

Reported results will be based on approved datasets and documented calculations.

## 20. Management Use of M&E Information

M&E information will be used as a management tool rather than solely as a reporting requirement.

The project will use evidence to identify performance gaps, investigate causes, determine corrective action, allocate attention and resources, and support adaptive management.

### 20.1 Performance Review Process

Management review will follow:

**Identify Variance → Investigate Cause → Review Evidence → Agree Corrective Action → Assign Responsibility → Set Deadline → Monitor Follow-up**

### 20.2 Corrective Action

Corrective actions may include:

- Additional technical support.
- Changes to training delivery.
- Increased field supervision.
- Revision of beneficiary engagement approaches.
- Strengthening of market-linkage activities.
- Additional MSME business support.
- Improvement of data collection procedures.
- Targeted support for underperforming beneficiary groups or locations.

Corrective actions will be documented with:

- Issue.
- Evidence.
- Agreed action.
- Responsible person.
- Deadline.
- Follow-up status.

### 20.3 Example: Low Adoption Performance

If adoption of at least three recommended practices is below target, the M&E team will not assume that training delivery alone explains the variance.

The review will examine:

- Training coverage.
- Attendance and completion.
- Knowledge assessment results.
- Access to inputs.
- Access to extension services.
- Demonstration plot exposure.
- Value-chain characteristics.
- Gender and age differences.
- Cost or affordability constraints.
- Farmer-reported barriers.
- Local implementation conditions.

The findings will then inform corrective action and subsequent monitoring.

### 20.4 Evidence-Based Management

Management decisions will be supported by a combination of:

- Indicator performance.
- Data quality evidence.
- Implementation records.
- Beneficiary feedback.
- Field observations.
- Contextual information.
- Lessons from previous implementation periods.

This approach will strengthen evidence-based decision-making and reduce the risk of making management decisions from isolated indicators.

## 22. Evaluation Approach

The ALMDP evaluation approach will assess the relevance, effectiveness, efficiency, sustainability, and contribution of project interventions.

### 22.1 Evaluation Questions

Evaluation will consider:

- **Relevance:** Are project interventions addressing identified beneficiary and market needs?
- **Effectiveness:** Are project activities and outputs contributing to intended outcomes?
- **Efficiency:** Are resources and implementation processes being used effectively?
- **Sustainability:** Are benefits and capacities likely to continue beyond project support?
- **Contribution:** What evidence indicates that project interventions contributed to observed changes?

### 22.2 Evaluation Evidence

Evaluation evidence may include:

- Baseline data.
- Midline findings.
- Endline findings.
- Routine monitoring records.
- Beneficiary surveys.
- Administrative records.
- Field observations.
- Beneficiary feedback.
- Qualitative evidence.
- Contextual information.
- Project implementation records.

### 22.3 Evaluation Timing

Formal evaluation activities will be aligned with the project's measurement cycle and may include midline and endline assessments.

Evaluation activities will be planned sufficiently in advance to ensure appropriate data availability, methodological consistency, and stakeholder participation.

### 22.4 Evaluation Independence

Where a formal external evaluation is commissioned, the evaluation design, analysis, and findings should maintain sufficient independence from routine project implementation and reporting functions.

## 23. Contribution Rather Than Attribution

The ALMDP M&E system will distinguish between project contribution and direct attribution.

The project operates within a broader economic, environmental, agricultural, policy, and market context. Changes in beneficiary outcomes may therefore be influenced by factors beyond project control.

### 23.1 External Factors

Relevant external influences may include:

- Weather and climate variability.
- Commodity prices.
- Input prices.
- Inflation.
- Government policies.
- Market conditions.
- Conflict and insecurity.
- Agricultural pests and diseases.
- Infrastructure conditions.
- Other development interventions.
- Macroeconomic conditions.

### 23.2 Contribution Analysis

Interpretation of project results will consider whether the evidence supports a credible contribution pathway between:

**Project Inputs → Activities → Outputs → Outcomes → Longer-Term Results**

The analysis will examine whether expected outputs were delivered, whether beneficiaries were reached, whether intermediate changes occurred, and whether the observed results are consistent with the project's Theory of Change.

### 23.3 Attribution Caution

The M&E system will not claim that all observed changes were caused exclusively by the project unless the evaluation design provides sufficient evidence to support such a conclusion.

Instead, findings will describe the project's contribution to observed results and identify important alternative explanations where relevant.

### 26.7 Data Retention and Disposal

Data retention, archiving, and disposal will follow project requirements and applicable policies.

- Proposed change.
